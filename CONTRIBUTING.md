# Contributing to CLogic Dialogue System

Thank you for your interest in contributing to the CLogic Dialogue System.

Contributions may include bug fixes, new features, documentation improvements, examples, tests, and other improvements to the project.

## Before Contributing

Before making a substantial change, consider opening an issue first to discuss the proposed change. This helps avoid duplicated work and ensures that the change fits the direction and architecture of the project.

For smaller bug fixes, documentation corrections, and similarly focused changes, you may submit a pull request directly.

## Pull Requests

When submitting a pull request:

- Target the `dev` branch unless instructed otherwise.
- Keep the pull request focused on a single change or closely related set of changes.
- Clearly describe what the change does and why it is needed.
- Document any breaking changes or changes to public APIs.
- Follow the existing code style and architecture of the project.
- Update relevant documentation when behavior or public APIs change.
- Test your changes before submitting them.
- Do not include unrelated formatting, generated files, or other unnecessary changes.

A contribution may be modified, declined, or removed at the discretion of the maintainers.

## Issues and Bug Reports

When reporting a bug, include enough information to reproduce the problem where reasonably possible, including:

- the Unity version;
- the CLogic Dialogue System version or commit;
- steps to reproduce the issue;
- expected behavior;
- actual behavior; and
- relevant errors, logs, screenshots, or minimal reproduction examples.

Please remove credentials, license keys, personal information, and other sensitive information before posting logs or project files.

## Feature Requests

Feature requests are welcome. Describe the problem or use case the feature would address rather than only describing a proposed implementation.

Large architectural changes should generally be discussed before implementation.

## Development

Follow the repository's existing project structure, naming conventions, and coding style.

Avoid introducing new dependencies unless they are necessary. New dependencies must have licensing terms compatible with the CLogic Dialogue System's distribution and licensing model.

Where practical, changes should remain compatible with the Unity versions officially supported by the project.
